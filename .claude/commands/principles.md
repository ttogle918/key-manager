# /principles — 설계 원칙 (key-manager)

구현·리팩터 전 빠르게 훑는 체크리스트. 예시는 이 저장소 코드 기준.

## SOLID + CoI

1. **SRP (단일 책임)** — 하나의 모듈은 한 가지 이유로만 바뀐다.
   - 예: `analyze()`는 조율만, 마스킹은 `masking.py`, 암호화는 `crypto.py`, 세션은 `vault_session.py`.

2. **OCP (개방-폐쇄)** — 확장에 열림, 수정에 닫힘.
   - 예: **지식베이스** — 새 서비스는 `knowledge/*.yaml` 한 개 추가로 끝(분류 코드 수정 0). 이 프로젝트의 핵심 확장점.

3. **LSP (리스코프 치환)** — 하위가 상위를 완전히 대체.
   - 예: Stage1(값)·Stage2(맥락)이 동일 계약 `ClassifiedItem`을 내보내 파이프라인이 균일하게 병합.

4. **ISP (인터페이스 분리)** — 안 쓰는 것에 의존하지 않게 쪼갠다.
   - 예: `vault_repo`(저장·암호문) / `vault_session`(세션·인증) 분리. 프론트 `api/client`는 도메인별 함수로.

5. **DIP (의존 역전)** — 고수준은 추상에 의존.
   - 예: `pipeline.analyze`는 `KnowledgeBase` 추상에 의존(구체 YAML 로딩과 분리). `clock` 주입으로 시간 테스트.

6. **CoI (상속보다 조합)** — 조합으로 확장.
   - 예: OCR은 `reconstruct`(순수 함수) + `ocr`(엔진 어댑터) 조합. 값 정밀화는 2차 인식 단계로 조합.

## 이 프로젝트만의 원칙 (도메인 규칙)

- **단정 금지**: 값만으로 애매하면(UUID·32hex) 절대 단정하지 않고 `conflict`/`unknown`으로 안전 분류 → 사용자 확인. (차별점의 핵심)
- **정직한 산출물**: UI·문서는 실제 구현 상태와 일치해야 한다. "구현 예정"을 "완료"로, 혹은 반대로 표기하지 않는다(보안 감사 1-1의 교훈).
- **시크릿 위생**: 실제 키·복호화된 값을 코드·테스트·문서·로그·커밋 메시지에 남기지 않는다. 더미만.
- **허용적 라이선스 전용**: 새 의존성은 반드시 `license-auditor` 선심사(MIT/Apache-2.0/BSD/ISC). 카피레프트·MPL 금지.
- **재현성**: 설치 한 번으로 실행. 무거운 자산(WASM·언어데이터)은 벤더 스크립트로 로컬 번들.
- **테스트 동반**: 엔진·크립토·저장소 변경은 pytest, 순수 프론트 로직은 vitest를 함께 바꾼다.

## 확인 후

원칙 위반 신호가 보이면(한 함수가 두 이유로 바뀜, 새 서비스인데 코드 수정 필요, 추상 없이 구체 결합)
멈추고 구조를 먼저 정리한다. 애매하면 `/done` 전에 `/code-review`로 점검.
