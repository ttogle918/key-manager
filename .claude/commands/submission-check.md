# 대회 제출 최종 점검 (2026 오픈소스 개발자대회)

## A. 저장소 상태 (평가는 각 시점의 저장소 상태 기준 — 규정 제11조)
- [ ] main 브랜치가 현재 커밋에서 README대로 설치·실행 가능한가
- [ ] 저장소가 Public 상태인가 (수상 시 5년 유지 의무 — 규정 제10조)
- [ ] `LICENSE`(MIT) 루트 존재
- [ ] `THIRD-PARTY-NOTICES.md` 존재 + 실제 의존성과 대조 일치
- [ ] `/license-check` 전 항목 ✅
- [ ] `/pre-commit` 전 항목 ✅ (특히 시크릿 스캔)

## B. 제출 파일 (홈페이지 온라인 제출)
- [ ] 결과보고서 DOCX(또는 HWPX) 1부 — 파일명 `2026 오픈소스 개발자대회 결과보고서_접수번호(팀명)`
- [ ] 동일 내용 PDF 1부
- [ ] 본문 5페이지 이내, 맑은고딕 10pt, 여백 임의 변경 없음, 안내 페이지·회색 가이드 문구 삭제
- [ ] 붙임1 SBOM: 저장소의 실제 `requirements.txt`/`package.json`과 항목·버전 일치 확인 (여기서 불일치가 라이선스 검증 감점 포인트)
- [ ] 붙임2 AI 모델 명세: 모델 미탑재 시 유형 체크 없이 4번 항목에 상용 AI 보조도구 활용 범위만 기재 (예: "코드 작성·디버깅 보조로 Claude 활용, 전체 코드의 약 N%")
- [ ] 시연영상 3분 이내, 유튜브 업로드 완료, URL 접근 가능(비공개 아님 — '일부공개(unlisted)' 이상)
- [ ] 프로젝트명·팀명이 접수 정보와 완전 일치 (상장에 그대로 기재됨)

## C. 규정 리스크 재확인
- [ ] 출품작 자체에 상용 API 전용 모델 연동이 없는가 (규정 제9조 — 로컬 구동 필수)
- [ ] 정부 지원사업 수혜 이력 발생 여부 — 있으면 중복수혜 확인서 작성 + 7일 내 신고 의무(규정 제15조 제2항)
- [ ] 영상·스크린샷에 실제 키가 노출된 프레임이 없는가 (데모는 더미 키로만)
