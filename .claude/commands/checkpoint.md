# /checkpoint — 작업 상태 저장 (세션 핸드오프)

긴 세션 중간에 지금까지의 진행을 파일로 남겨, 다음 세션(또는 컨텍스트 요약 후)이 바로 이어받게 한다.
**커밋하지 않는다** — 작업 트리에 메모만 남긴다. (`docs/CHECKPOINT.md`는 `.gitignore`에 두는 것을 권장.)

## 실행 흐름

1. 현재 상태를 파악한다.
   ```bash
   git branch --show-current
   git log --oneline -5
   git status --short
   ```
   진행 중인 TASK(BACKLOG의 `🔄`/작업 중), 방금까지 만진 파일, 다음 할 일을 정리한다.

2. `docs/CHECKPOINT.md`를 아래 형식으로 **덮어쓴다**(이전 체크포인트는 대체).

   ```markdown
   # WIP 체크포인트 — <TASK/기능 이름>
   **저장 시각**: YYYY-MM-DD HH:MM  ·  **브랜치**: <branch>

   ## 완료한 것 (이번 세션)
   - <커밋 해시·요약 또는 미커밋 완료 항목>

   ## 진행 중 (미커밋)
   - `경로/파일` — 무엇을 하던 중이었는지
   - 게이트 상태(테스트·빌드 통과 여부)

   ## 다음에 이어서 할 일
   1. …
   2. …

   ## 막힌 점 / 결정 필요 (없으면 생략)
   - …

   ## 실행 중인 로컬 서버·임시자원 (있으면 — 정리 대상)
   - 예: 백엔드 :80xx, dev :51xx, 임시 vault.db 경로
   ```

3. 저장한 경로를 알려주고, 미커밋 변경이 있으면 `/done`으로 마무리할지 물어본다.

## 규칙
- 실제 값(키·시크릿)이나 복호화된 값을 체크포인트에 절대 적지 않는다(CLAUDE.md 시크릿 위생).
- 코드는 바꾸지 않는다. 상태 기록만.
