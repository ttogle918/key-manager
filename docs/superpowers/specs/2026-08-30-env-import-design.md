# `.env` 가져오기 + 저장 전 인라인 편집 설계

> 지금 KeyLens는 `.env` **내보내기**만 있다. 반대 방향 — 이미 쓰던 `.env` 파일을 끌어다 놓으면
> 컬렉션과 변수들을 만들어 주는 기능 — 이 없다. 이 설계는 그 공백을 메운다.
> 범위는 **저장 전 단계**로 한정한다. 이미 금고에 저장된 항목의 변수명 변경은 암호화 경로를
> 건드리므로 별도 스펙으로 뺀다(아래 "범위 밖" 참고).

## 배경

`keylens-env` SDK가 나오면서 `.env` 파일 없이 코드에서 바로 키를 불러 쓸 수 있게 됐다. 그런데
**이미 `.env`를 쓰고 있던 레포를 KeyLens로 옮기는 경로가 없다.** 지금은 키를 하나씩 손으로
다시 입력해야 한다. 변수가 10개면 10번이다.

`.env` 내용을 텍스트 칸에 붙여넣으면 분류는 되지만 두 가지가 어긋난다:

1. **원본 변수명이 유실된다.** `MY_CUSTOM_NAME=ghp_...` 를 넣으면 지식베이스의 공식 이름인
   `GITHUB_TOKEN` 으로 저장된다. 소비 레포 코드는 이미 `os.environ["MY_CUSTOM_NAME"]` 을
   읽고 있으므로, 이름이 바뀌면 코드를 전부 고쳐야 한다 — 방향이 반대다.
2. **컬렉션이 자동으로 안 붙는다.** `/analyze` 응답에 `project` 필드 자체가 없어서, 저장할 때
   손으로 넣어야 하고 안 넣으면 등록일 이름의 컬렉션으로 새어 나간다
   (`docs/memo/2026-08-29-runtime1-e2e-bug-audit.md` 2번 참고).

## 목표

- `.env` 파일을 앱에 끌어다 놓으면 **한 화면에서** 전 변수를 확인하고 일괄 저장한다.
- **원본 `.env` 변수명을 그대로 지킨다.** 지식베이스 공식 이름은 "제안"으로만 보여준다.
- 이름·값을 **더블클릭으로 그 자리에서** 고칠 수 있다.
- **한 줄도 조용히 잃지 않는다.**

## 범위 밖 (별도 스펙)

**이미 저장된 항목의 변수명 변경.** `official_name` 이 암호문의 AAD로 묶여 있어
(`vault_repo._aad`), 이름을 바꾸려면 값을 **재암호화**해야 한다. `PATCH /vault/entries/{id}` 는
현재 `project`·`memo`·`expires_at` 만 받는다. 이건 메타데이터 편집이 아니라 암호화 경로 수정이라,
재암호화 실패 시 값 소실 가능성까지 따져야 하는 별도 작업이다. 이 스펙에 얹으면 검토가 뭉개진다.

**보관함의 "값" 더블클릭 편집은 이 스펙에 포함한다** — 새 백엔드가 필요 없기 때문이다.
이미 있는 `POST /vault/entries/{id}/rotate`(회전, 이력 기록) 흐름에 연결하기만 하면 된다.

## 결정 1 — 전용 모달, 내부는 기존 `/analyze` 재사용

**결정**: `.env` 를 드롭하면 전용 가져오기 모달(체크박스 표)을 띄우되, 분류는 기존
`POST /analyze` 를 그대로 호출해서 받는다. **백엔드 변경 없음.**

**왜**: 기존 결과 카드 흐름을 그대로 쓰면(대안 A) 변수 20개짜리 `.env` 에 카드 20장이 쌓인다.
결과 카드는 스크린샷에서 키 두어 개 나오는 걸 전제로 만든 화면이다. 반대로 파싱·분류까지 전부
새로 만들면(대안 B) 검증된 파이프라인을 버리게 된다. 표시만 새로 만들고 분류는 재사용한다.

## 결정 2 — `.env` 가 진실, `/analyze` 는 보강

**결정**: 프론트가 `.env` 텍스트를 직접 스캔해 **이름·값 전체 목록**을 만들고, `/analyze` 결과는
**값으로 매칭해 분류 정보(service·kind·신뢰도·라벨)만 얹는다.**

```
.env 텍스트 ─┬─ 프론트 최소 스캔 (KEY=VALUE)  → 이름·값 전체 목록 (손실 0)
             └─ POST /analyze                → 값 매칭으로 service·kind·신뢰도 보강
```

**왜**: `stage1` 이 **값 기준으로 중복 제거**한다. 실측 확인:

```
FOO=ghp_2222...
BAR=ghp_2222...      (같은 값, 다른 이름)   →  /analyze 는 1건만 반환. BAR 소실.
```

`.env` 에서 두 변수가 같은 값을 갖는 건 흔하다(`DATABASE_URL` / `DB_URL`). 백엔드 응답만
믿으면 변수가 조용히 사라진다 — 오늘 고친 "조용한 손실" 부류와 같은 실패다. 백엔드의 값 기준
중복 제거는 스크린샷 경로에서는 옳은 동작이므로 건드리지 않고, `.env` 경로에서만 프론트가
권위 있는 목록을 만든다.

**프론트 파서가 처리할 것** (백엔드 파서 실측으로 확인된 범위와 동일하게 맞춘다):

| 입력 | 결과 |
|---|---|
| `KEY=value` | 그대로 |
| `KEY="value"` / `KEY='value'` | 따옴표 벗김 |
| `export KEY=value` | `export ` 제거 |
| `KEY = value` | `=` 주변 공백 제거 |
| `KEY=value  # 주석` | 인라인 주석 제거 |
| `# 주석줄` / 빈 줄 | 건너뜀 |
| `KEY=` (빈 값) | 건너뜀 |
| `=value` (이름 없음) | 건너뜀 |

여러 줄 값(`KEY="줄1\n줄2"`)은 지원하지 않는다 — 시크릿에는 사실상 안 쓰이고, 지원하면 파서가
훨씬 복잡해진다. 해당 줄은 첫 줄만 값으로 잡힌다.

## 결정 3 — 변수명은 원본 우선

**결정**:

```
프론트 파서가 읽은 이름  →  항상 이것이 기본값
그것이 없을 때만        →  official_env_name (지식베이스)
둘 다 없으면            →  빈 칸 (저장 불가 표시)
```

지식베이스 공식 이름은 다르면 **"제안: GITHUB_TOKEN [적용]"** 으로 옆에 보여주고, 누르면 바뀐다.

**왜**: 소비 레포 코드가 이미 원본 이름을 읽고 있다. 공식 이름으로 바꾸면 KeyLens 를 도입하는
대가로 코드를 고치게 만드는 셈이다.

## 결정 4 — 비시크릿 줄도 전부 가져온다

**결정**: `DB_HOST=localhost` 처럼 분류가 `unknown` 인 줄도 목록에 넣고 **기본 체크 상태**로 둔다.

**왜**: 목표가 `.env` 파일 자체를 없애는 것이다. `DB_HOST` 가 KeyLens 에 안 들어오면 레포에
`.env` 를 계속 둬야 하고, 그러면 도입한 의미가 절반이 된다. 사용자가 원하면 체크를 끄면 된다.

**주의**: `official_name` 이 없는 항목은 `entries_for_env` 가 건너뛰므로 SDK 로 내려가지 않는다.
이 경로에서는 프론트가 항상 원본 이름을 넣으므로 그 문제가 생기지 않는다.

## 결정 5 — 인라인 편집은 더블클릭

**결정**: 이름·값을 더블클릭하면 그 자리에서 입력 상태로 바뀐다. 편집 중임이 눈에 띄어야 한다 —
테두리가 진해지고 커서가 깜빡인다.

적용 위치:
- `.env` 가져오기 표 (이름·값)
- 결과 카드 (변수명) — 스크린샷·텍스트 경로에서도 이름을 고칠 수 있어야 하므로
- 보관함 (값만) → 더블클릭하면 **기존 회전 모달(`RotateModal`)을 연다.** 표 안에서 값을 직접
  고쳐 쓰는 게 아니다 — 값 교체는 재암호화 + 이력 기록이 따라야 하고 그 경로가 이미 있다.
  더블클릭은 "회전" 버튼을 찾아 누르는 수고를 줄이는 지름길일 뿐이다. **이름은 범위 밖.**

새 저장 로직이 필요 없다.

## 엣지 케이스

| 상황 | 처리 |
|---|---|
| 변수명 비어 있음 | 저장 불가 표시, 체크 해제 강제 |
| 같은 컬렉션에 같은 변수명 존재 | 기존 `findDup` 재사용 — 중복 표시 후 건너뜀 |
| 컬렉션 미입력 | **저장 버튼 비활성.** 등록일 컬렉션으로 새는 것을 원천 차단 |
| 금고 잠김(401) | 기존 처리 재사용 — "잠금을 해제하세요" |
| 저장 중 일부 실패 | 성공분은 목록에서 제거, 실패 항목만 남겨 재시도 가능 |
| 파일이 `.env` 가 아님 | 파싱 결과 0건이면 "환경변수를 찾지 못했어요" 안내 |
| 큰 파일 | 1MB · 200줄 상한. 초과 시 안내하고 중단 |
| 백엔드 미기동 | `.env` 파싱은 되지만 분류가 없다 → 분류 없이 목록만 보여주고 저장 진행 |

**시크릿 노출**: `/analyze` 응답의 `meta.context` 에는 **다른 줄의 시크릿 평문이 통째로** 들어 있다
(Stage2 라벨 매칭용). `.env` 는 한 파일에 시크릿이 여러 개라 이게 도드라진다.
**가져오기 표에서는 `context` 를 쓰지 않는다.** 값은 항상 마스킹해 보여주고, 더블클릭으로 편집
상태에 들어갔을 때만 평문을 노출한다.

## 테스트

**`envParse.test.ts`** (vitest, `lib/format.test.ts` 옆)
- 따옴표(쌍/홑) 벗기기, `export ` 접두어, `=` 주변 공백, 인라인 주석, 주석줄·빈 줄 건너뛰기
- 빈 값 · 이름 없는 줄 건너뛰기
- **같은 값 다른 이름 2줄이 2건으로 남는지** — 결정 2의 핵심, 회귀하면 변수가 조용히 사라진다
- 여러 줄 값은 첫 줄만 잡히는지(문서화된 한계 고정)

**변수명 결정 규칙**
- `.env` 이름 있으면 그것, 없으면 `official_env_name`, 둘 다 없으면 빈 칸

**인라인 편집**
- 더블클릭 → 편집 상태 전환, 저장 시 값 반영
