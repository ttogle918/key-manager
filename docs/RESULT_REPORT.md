# KeyLens — 결과보고서

> **한 줄 정의**: 스크린샷·URL을 던지면 "이건 Notion API 키, 이건 database ID"처럼 **출처의 맥락으로 정체를 가려**
> 공식 환경변수명에 매핑하고, 마스터 비밀번호로 **암호화해 나만 볼 수 있게** 보관하는 개인 개발자용 자격증명 관리 도구.
>
> 오픈소스 개발자대회 자유과제(보안) · 솔로 · MIT.

## 1. 문제 정의

### 1-1. 개발배경 — 2일짜리 AI 활용 보수교육 보조강사로 본 것

참가자는 강사 대상 2일짜리 AI 활용 보수교육에 보조강사로 참여하고 있다. 실습은 항상 "배포까지 마쳐서
본인 홈페이지를 직접 보는 것"을 목표로 하다 보니, 교육생 한 명이 OpenAI API 키·Google AI Studio·
Google Cloud·Supabase·Vercel 같은 무료 배포 툴, Tavily 검색 키 등 온갖 키를 받아 적용해야 했고, 많을
때는 2일 동안 **20개 넘는 키**를 발급받는 날도 있었다.

보조강사에게 가장 많이 들어온 질문은 거의 항상 같았다 — "이 키가 무슨 키예요?", "방금 받은 게 뭐고
어디 환경변수에 넣어야 해요?" 특히 **Notion**에서 헷갈려 했다. 변수·키처럼 딱 떨어지는 형태로 나오지
않고, URL에서 값을 따야 하고, 화면의 "표"가 사실 database라는 걸 알아야 하고, 그 database의 id를 다시
찾아야 하고, 설정에 들어가 webhook 같은 항목까지 확인해야 한다 — 화면 여러 곳에 흩어진 맥락을 스스로
조합해야 정체를 알 수 있는 구조다. 강사님 화면을 따라가다가 "여기까지는 따라했는데, 이 화면에서 뭐가
키인지 모르겠다"는 순간이 반복적으로 발생했다.

발급받은 키는 보통 메모장에 적어두는데, 이건 교육생 본인 소유라 집에 가져가고 싶어 하는 게 당연하다.
그런데 초기화하지 않고 그냥 자리를 뜨는 사람도 있고, 반대로 실습 중 만든 자료·결과물 파일을 일일이
지우느라 늦게까지 남는 사람도 많았다 — 정리 자체가 부담스러운 일이 되어 있었다. 또 `.env` 파일처럼
개발자다운 방식으로 관리하고 싶어 하는 사람도 많았지만, `dotenv` 패키지를 코드에 적용하는 것 자체를
어려워했다.

**기존 시크릿 스캐너(TruffleHog·Gitleaks 등, 정규식 기반)는 정확히 이 지점에서 손을 든다.** Notion의
`database_id`·`data_source_id`·`page_id`는 **전부 같은 32자리 UUID**라 값만 봐서는 구분이 불가능하고,
Kakao는 REST/JavaScript/Admin/Native 키가 한 화면에 비슷하게 나열된다. 값의 형식이 같으면 "여러 후보
가능"이라며 구분을 포기하는 것이다.

### 1-2. 목적

1. 화면 캡처 한 장만 있으면 그 자리에서 "이게 무슨 키인지" 맥락으로 설명해주고 표준 변수명으로
   정리해주는 것 — 강사님을 따라가다 막히는 순간에 즉석에서 도움을 받을 수 있게(화면 설명 기능의
   직접적 동기, §4).
2. 발급받은 키를 코드·패키지 지식 없이도 안전하게 암호화해 보관하고, 필요하면 암호화된 채로 가져갈 수
   있게 하는 것 — `dotenv`를 몰라도 UI에서 `.env` 파일을 바로 내려받거나 복사해 쓸 수 있게.
3. 실습이 끝나면 자격증명 정리 부담 없이 마음 편히 자리를 뜰 수 있게 하는 것 — 항목별 삭제와 암호화
   번들 교체는 물론, 사이드바의 "금고 완전 초기화" 버튼으로 **한 번에 비우는 원클릭 완전 초기화**까지
   지원한다(§8).

## 2. 차별점 — 값이 아니라 **출처의 맥락**으로 분류한다 (프로젝트의 심장)

KeyLens는 값 자체가 아니라 **값이 있던 자리의 맥락**(스크린샷 속 라벨, URL 구조)을 분류 신호로 쓴다.

- **2단계 분류 엔진**
  - **Stage 1 (값 기반)**: 접두어가 명확한 키(`sk-` OpenAI, `AIza` Google, `secret_`/`ntn_` Notion, `<32hex>.<24base62>` Ollama)를 정규식으로 즉시 식별.
  - **Stage 2 (맥락 기반) ★차별점**: 값만으론 애매한 키(UUID·32hex)를 **주변 라벨**("Database ID", "REST API 키")과 **URL 구조**(`notion.so/…?v=` 앞 세그먼트 = database_id)로 가려낸다.
- **단정 금지가 원칙**: 라벨과 URL 신호가 충돌하면 임의로 단정하지 않고 **"확인 필요(conflict)"** 로 두 후보를 제시해 사용자가 고르게 한다. — 잘못된 확신보다 정직한 미결이 낫다.

> **한 문장 반박**: "기존 도구는 `3f9a1c2e…` 를 보고 '32자리 hex'라고만 말하고 멈춘다. KeyLens는 그 값 **위에 적힌 'Database ID'** 를 읽어 `NOTION_DATABASE_ID` 라고 답한다."

**실측**: 실제 Ollama 콘솔 스크린샷 → 백엔드 OCR(RapidOCR) → `OLLAMA_API_KEY`(high) 분류까지 엔드투엔드 확인. 노션 DB URL은 `database_id`, page URL은 `page_id`로 구분.

## 3. 아키텍처 — 로컬 우선(local-first), 외부 서버 없음

```
[ React + TypeScript 프론트엔드 (:5173) ]      ←→   [ FastAPI 로컬 백엔드 (:8003, 127.0.0.1 전용) ]
  ├─ 상태: Zustand                                     ├─ OCR: RapidOCR(PP-OCRv5 한국어 인식)
  ├─ UI: 입력·결과카드·보관함·잠금                          │    └ 이미지가 기기를 떠나지 않음, 디스크 미저장
  └─ MUI DataGrid: 분석 결과 요약                          ├─ 분류 엔진 (Stage1 값 / Stage2 맥락)
                                                        ├─ 화면 설명(옵트인) → 로컬 Ollama 호출
                                                        ├─ 지식베이스 로더 (knowledge/*.yaml)
                                                        └─ 암호화 저장소
                                                             ├ crypto.py  (Argon2id + AES-256-GCM)
                                                             ├ vault_repo.py (SQLite — 암호문만)
                                                             └ vault_session.py (세션 인증·자동잠금)
```

- **로컬 우선**: 외부 서버·클라우드가 없다. 모든 데이터는 사용자 기기에만 존재하며 네트워크로 전송되지 않는다(백엔드도 `127.0.0.1` 전용).
- **OCR을 백엔드 RapidOCR로**: 초기에는 브라우저 `tesseract.js`(WASM)를 썼으나, 한글 단일 글자 라벨("키"/"앱") 오독으로 Kakao 4종 키 중 2종이 `unknown`으로 빠지는 문제가 있어 RapidOCR의 한국어 PP-OCRv5 인식 모델로 교체했다. 실행 위치는 여전히 이 기기 안(로컬 백엔드)이라 이미지는 디스크에 저장되지 않고 외부로도 나가지 않는다 — 로컬 우선 원칙 그대로 유지. 가중치는 해시 검증 후 빌드 시 로컬 벤더링(런타임 CDN 미사용). 옛 브라우저 경로(`frontend/src/ocr/*`)는 재구성 로직 회귀 테스트용으로만 남아 있다.
- **화면 설명(옵트인, 신규)**: "이 화면 설명해줘" 버튼으로 스크린샷 전체를 박스+라벨로 설명. 지식베이스에 이미 등록된 서비스는 즉시 라벨링하고, 미등록 영역만 사용자가 이미 실행 중인 로컬 Ollama에 짧은 설명을 요청한다. 앱은 어떤 LLM 가중치도 포함하지 않으며, `OLLAMA_MODEL` 미설정 시 기능 자체가 화면에 나타나지 않는다(조용한 저성능 대체 없음). 상세는 [붙임2 AI 모델 활용 명세서](./AI_MODEL_DISCLOSURE.md).
- **분류와 OCR 분리**: 차별점(맥락 분류)을 OCR 안정성에 인질로 잡히지 않게, text·URL 신호로 먼저 완성하고 OCR은 "이미지→텍스트+라벨" 입력 경로로 붙였다.

## 4. 핵심 기능

| 기능 | 설명 |
|---|---|
| **다양한 입력** | 콘솔 스크린샷(드래그·붙여넣기), URL, 텍스트 |
| **2단계 분류 + 공식 변수명 매핑** | 분류 결과를 `NOTION_DATABASE_ID`·`KAKAO_REST_API_KEY` 등 표준 환경변수명으로 정리 |
| **값 정밀 재인식** | OCR 값 오독을 값 영역만 PSM+charset로 2차 인식해 교정(길이 가드로 퇴행 방지). 불확실 지점은 빨간 표식+토스트로 안내 |
| **암호화 금고** | 마스터 비밀번호 → Argon2id 키 → AES-256-GCM으로 값 암호화, SQLite에 암호문만 저장 |
| **인증 게이트** | 값 조회·복사·내보내기 전 인증. 무활동 자동 잠금, 연속 실패 백오프 지연 |
| **감사 이력** | 등록·열람·복사·내보내기·키 교체를 기록(값 없이) — 유출 시점 역추적 |
| **키 회전** | 서비스에서 재발급한 새 값으로 교체(재암호화, 옛 값 폐기) |
| **`.env` 내보내기** | 선택 키를 표준 변수명으로 내보내기(인증 후, 평문 노출 경고) |
| **확장 가능한 지식베이스** | 서비스 정의가 YAML — 파일 하나 추가로 새 서비스 지원(코드 수정 0) |
| **화면 설명(옵트인, 신규)** | "이 화면 설명해줘" 버튼으로 스크린샷 전체를 박스+라벨 오버레이로 설명. 미등록 영역만 사용자의 로컬 Ollama에 질의(가중치 미포함, 미설정 시 기능 자체 숨김) |

## 5. 보안 설계

- **키 유도**: 마스터 비밀번호 → **Argon2id**(메모리-하드 KDF)로 32B 키 유도. 솔트·파라미터만 저장하고 **유도된 키는 메모리에만** 존재, 잠금 시 폐기.
- **암호화**: 항목별 **AES-256-GCM**(인증 암호화), 매 암호화마다 고유 nonce. GCM 태그로 변조·오답 비밀번호를 거부. 항목을 `official_name`에 AAD로 묶어 DB 라벨 스왑 변조까지 탐지.
- **저장**: SQLite에는 **암호문·nonce·메타데이터만** — 평문 값 컬럼 자체가 없다. 파일을 직접 열어도 평문 미노출(바이트 스캔 테스트로 검증).
- **접근 통제**: 조회·복사·내보내기 전 인증 필수, 무활동 자동 잠금(기본 5분, 설정 가능), 연속 실패 시 지수 백오프.
- **정직한 산출물**: 자체 보안 감사(SECURITY_REVIEW.md)를 수행하고, "구현 예정"을 "완료"로 표시하는 등의 **허위 보안 표시를 전부 제거**했다. UI·문서가 실제 구현 상태와 일치한다.

**방어 범위 밖(한계, 정직하게 명시)**: 이미 장악된 호스트(키로거·메모리 덤프), 약한 마스터 비밀번호. KeyLens는 **분실·도난 기기의 디스크 접근, 파일 유출, 저장소 직접 열람**으로부터 보호한다.

## 8. 한계 (정직하게)

- **OCR 값 정확도**: 고엔트로피 시크릿의 완벽한 OCR은 엔진을 바꿔도 본질적으로 불안정하다(예: 숫자 `1`↔글자 `i`). 초기 브라우저 `tesseract.js`는 한글 단일글자 라벨("키"→"7|")까지 반복 오독해 백엔드 RapidOCR로 교체했지만(§3), 값 자체의 완벽 인식은 여전히 보장하지 않는다. 그래서 **값은 복붙을 전제**로 두고, OCR은 "무슨 키인지 분류"에 집중하며 불확실 지점을 사용자에게 표식으로 알린다. 전역 이미지 전처리는 실험 결과 오히려 퇴행이라 채택하지 않았다.
- **검출 범위**: 값 기반 자동 검출은 지식베이스 등록 서비스 기준(현재 **9종**: Notion·Kakao·GCP·OpenAI·Ollama·GitHub·AWS·Slack·Stripe). 새 서비스는 **YAML 한 개 추가로 백엔드·프론트 양쪽에 자동 반영**된다(프론트는 `/knowledge`를 런타임 소비 — 코드 수정 0). 접두어 없는 종류(AWS 시크릿 등)는 값 단정 없이 라벨 맥락(Stage2)으로만 식별하고, 미등록 키는 오식별 없이 `unknown` 처리(다만 화면 설명 기능이 옵트인 Ollama로 "무엇으로 보이는지" 설명은 해준다). 교육 현장에서 실제로 자주 마주친 **Supabase·Vercel·Google AI Studio·Tavily, Notion webhook 시크릿**은 아직 미등록 — 다음 지식베이스 확장 1순위(§10).
- **키 유효성 검증(TRUST-1) 범위**: 현재 검증 엔드포인트를 선언한 서비스는 OpenAI·Notion 2종(read-only 호출, active/invalid/unknown). 카카오·GCP 등은 인증 스킴이 상이해 미선언(unsupported)이며, 지식베이스 `verify:` 블록만 추가하면 확장된다.
- **서버리스 멀티 기기(SYNC-0)**: 암호화 번들 내보내기/가져오기(교체·병합)까지 구현. 파일 이동은 수동(USB·개인 클라우드)이며, 자동 동기화(SYNC-1, Google Drive `drive.appdata`)는 로드맵.
- **의존성 취약점(SCA)**: 프론트·백엔드 **전 영역 0건**(`npm audit --omit=dev` · `pip-audit`). starlette 를 패치본(**1.3.1**, `fastapi 0.139.0`)으로, pytest 를 **9.0.3** 으로 업그레이드해 알려진 CVE 전부 해소(테스트 258개 회귀 통과). 상세는 [SBOM §5](./SBOM.md).
- **미구현(의도적 로드맵)**: Google Drive 제로널리지 자동 동기화(SYNC-1)는 대회 이후 로드맵.
- **금고 완전 초기화(구현 완료)**: 사이드바의 "금고 완전 초기화" 버튼(`POST /vault/reset`)이 마스터 비밀번호 재확인 후 저장된 모든 자격증명·감사 이력·프로젝트 접근 승인 기록을 완전히 삭제하고 "초기화 안 됨" 상태로 되돌린다 — 교육·공용 PC 시나리오(§1-2 목적 3)를 실제로 지원한다.

## 8.5 배포·호스팅 로드맵 (설계 근거)

"다른 사람도 쓰게" / "아무 컴퓨터에서나 접속"이라는 요구를 어떻게 풀지에 대한 **의도적 설계 선택**을 남긴다.

### 왜 지금은 "웹 호스팅"이 아니라 "로컬 실행"인가

이 도구의 정체성은 **"키는 사용자 기기를 절대 떠나지 않는다(제로 널리지)"** 이다. 프론트만 Vercel 등에
올리는 건 백엔드(분류·암호화·금고)가 로컬에 있어 동작하지 않고, 백엔드까지 호스팅하면 **모든 사용자의
자격증명이 우리 서버로 모이는 허니팟**이 되어 정체성이 무너진다. 그래서 배포 형태를 **"각자 로컬 실행"**
으로 고정했다:
- **소스 배포**(git clone) + **데스크톱 앱**(PyWebView, `desktop/`) — 각 사용자 기기에서 로컬 실행
- **멀티 기기**는 호스팅이 아니라 **암호문 동기화**로: SYNC-0(암호 번들 수동 이동, 구현 완료) → SYNC-1(개인
  Drive `appDataFolder`에 암호문만 자동 동기화, 로드맵). 복호화 열쇠는 항상 로컬 마스터 비밀번호.

### "웹 로그인으로 어디서나" 를 하려면 (선행 조건)

로그인 자체는 **식별**일 뿐이며, 서버에 평문 키를 두면 로그인은 유출을 막지 못한다. 진짜 선결 과제는
**클라이언트 사이드 종단간(E2E) 암호화** — 서버는 평문을 절대 못 보고 암호문만 저장(Bitwarden/1Password
모델). 여기에 상태 저장(서버리스는 무상태 → 외부 DB 필요)·계정·키 복구·감사까지 얹으면 **대회 범위를
넘는 별도 대형 프로젝트**다. 따라서 이번 범위에서 제외하고, 착수 시 다음을 원칙으로 명시해 둔다:
- 서버는 **암호문만** 저장(마스터 비밀번호·유도 키·평문은 절대 전송·저장 안 함)
- 암호화/복호화는 **전적으로 클라이언트**에서(WebCrypto), 서버는 저장·동기화 중계만
- 그래도 계정 유출·서버 침해 시 키는 안전(제로 널리지 유지)

### 웹 존재감이 필요하면 (안전한 형태)

**랜딩/다운로드 페이지**(정적 사이트, GitHub Pages/Vercel)를 두고 [GitHub Releases](https://github.com/ttogle918/key-manager/releases)로
링크하는 것은 **사용자 키를 만지지 않으므로 안전**하다. 앱 자체를 서버로 올리는 것과는 전혀 다르다.

## 9. 재현성

```bash
# 설치 (처음 한 번)
cd backend && python -m venv .venv && .venv\Scripts\activate && pip install -r requirements.txt && cd ..
cd frontend && npm ci && cd ..
# 실행 (한 번에)
node scripts/dev.mjs         # 백엔드 :8003 + 프론트 :5173 동시 기동
```

- 의존성 버전 고정(requirements.txt / package-lock.json), 로컬 자산 자동 벤더링.
- **검증**: 백엔드 pytest 258개 · 프론트 vitest 45 + build · **브라우저 E2E**(설정→분석→암호화 저장→조회→잠금→인증) 통과 · 금고 번들 내보내기/가져오기 라이브 HTTP 라운드트립 확인.
- **데스크톱 앱**(선택): `cd frontend && npm run build` 후 `python desktop/app.py` — 네이티브 창으로 로컬 실행([`desktop/README.md`](./desktop/README.md)).
- 데모용 더미 스크린샷(`docs/demo/*.png`)으로 즉시 체험 가능.
