기능

키를 다루는 동안 생기는 사고를 막습니다

기능을 채운 게 아니라, 실제로 겪는 실패마다 대응을 붙였습니다.

분류

스크린샷·URL·텍스트에서 인식

콘솔 화면을 그대로 던지면 됩니다. OCR은 로컬 백엔드(127.0.0.1)에서 돌아가 이미지가 기기를 떠나지 않습니다.

분류

공식 환경변수명으로 정리

NOTION_DATABASE_ID처럼 각 서비스가 실제로 쓰는 이름에 맞춥니다. 매번 다르게 적어 생기는 혼선이 사라집니다.

보관

암호화 금고

마스터 비밀번호로 잠급니다. 저장 파일을 직접 열어도 평문 키는 보이지 않습니다.

보관

자동 잠금 · 감사 이력

자리를 비우면 잠깁니다. 언제 무엇을 열람·복사·내보냈는지 기록이 남습니다 — 값은 남기지 않고요.

사용

코드에서 바로 불러쓰기

keylens_env SDK로 .env 파일 없이 실행 중인 금고에서 값을 받아옵니다. 프로젝트별 접근 승인이 있어 등록 안 된 디렉토리는 요청해도 안 내려갑니다.

관리

살아있는 키인지 확인

버튼을 누르면 읽기 전용 호출 한 번으로 키가 아직 유효한지 확인합니다. 자동으로 호출하지 않습니다.

관리

노출 등급 표시

공개해도 되는 키와 절대 노출하면 안 되는 키를 구분해 표시합니다. 유출 시 피해와 대응 링크도 함께.

관리

만료 임박 알림

만료일을 넣어두면 임박한 것부터 위로 올라옵니다. JWT는 만료 시각을 자동으로 읽습니다.

이동

다른 기기로 옮기기

금고 전체를 암호화된 파일 하나로 내보냅니다. 서버를 거치지 않고 USB나 개인 클라우드로 옮기면 됩니다.

이해

이 화면 자체가 뭔지 설명

화면 전체를 박스+라벨로 짚어줍니다. 모르는 서비스는 로컬 Ollama가 추정하고, 원하면 웹 검색으로 다시 확인합니다 — 둘 다 옵트인, 안 켜면 전부 로컬에서 끝납니다.

확장

새 서비스는 파일 하나

서비스 정의가 YAML이라 코드를 고치지 않고 추가할 수 있습니다. 현재 9종을 지원합니다.

보안

키는 이 기기를 떠나지 않습니다

계정도, 클라우드도, 우리가 운영하는 서버도 없습니다. 분석과 보관이 전부 사용자 컴퓨터 안에서 끝납니다.

Argon2id
마스터 비밀번호에서 암호화 키를 유도합니다. 메모리를 많이 쓰도록 설계돼 대량 대입에 비용을 강제합니다.
AES-256-GCM
항목마다 개별 암호화하며 위조·변조를 함께 검증합니다. 비밀번호가 틀리면 복호화 자체가 거부됩니다.
저장되지 않는 것
마스터 비밀번호, 거기서 유도한 키, 평문 값. 디스크에는 암호문만 남고, 삭제한 항목은 secure_delete+VACUUM으로 복구 불가능하게 지웁니다.
네트워크
백엔드는 127.0.0.1에서만 동작합니다. 키 유효성 확인을 직접 누를 때, 그리고 옵트인 기능(화면 설명의 검색 확인·이메일 동기화)을 직접 켰을 때를 빼면 밖으로 나가는 통신이 없습니다.

정직하게 말하면: 이미 장악당한 컴퓨터(키로거·메모리 덤프)와 너무 쉬운 마스터 비밀번호는 막지 못합니다. KeyLens가 지키는 것은 기기 분실·파일 유출·저장소 직접 열람입니다.

FAQ

자주 묻는 것들

마스터 비밀번호를 잊으면 어떻게 되나요?+
복구할 방법이 없습니다 — 백도어를 두지 않았기 때문입니다. 대신 평소에 암호화 번들을 내보내 두면(아래 "다른 기기로 옮기기") 새 마스터 비밀번호로 다시 만든 금고에 가져와 복구할 수 있습니다.
여러 기기에서 쓸 수 있나요?+
서버 없이도 됩니다. 금고 전체를 암호화 번들 파일(.klvault.json)로 내보내 USB·개인 클라우드로 옮기거나, 계정 없이 SMTP로만 자기 자신에게 이메일로 전달(옵트인, 별도 배포)할 수 있습니다. 둘 다 암호문 상태로만 이동합니다.
왜 브라우저 확장이 아니라 로컬 앱인가요?+
화면 캡처·클립보드 접근 같은 광범위한 권한을 브라우저 확장에 상시로 주는 대신, 사용자가 스크린샷을 직접 붙여넣는 순간에만 동작하는 로컬 앱이 더 적은 권한으로 같은 일을 합니다.
소스코드를 안 믿으면요?+
전체 소스가 MIT로 공개돼 있고, 자체 보안 감사 문서(SECURITY_REVIEW.md)도 저장소에 그대로 공개돼 있습니다. 실행 파일을 받는 대신 직접 클론해서 빌드·실행할 수도 있습니다.
설치

둘 중 편한 쪽을 고르세요

실행 파일은 현재 Windows만 배포합니다. macOS·Linux는 소스로 실행하세요 — 코드는 플랫폼을 가리지 않습니다.

실행 파일 (Windows 권장)

내려받아 압축을 풀고 KeyLens.exe를 실행하면 끝입니다. 설치 과정도, 계정 가입도 없습니다.

최신 버전 받기

소스에서 실행 (모든 OS)

Python 3.11+ 와 Node 20+ 가 필요합니다.

# 처음 한 번
cd backend && python -m venv .venv
.venv\Scripts\activate && pip install -r requirements.txt
cd ../frontend && npm ci && cd ..

# 실행 — 백엔드와 프론트가 함께 뜹니다
node scripts/dev.mjs
개발자용

.env 파일 없이 키 불러오기

.env는 결국 평문 파일을 디스크에 남깁니다. keylens-env는 같은 한 줄 API를 쓰되 실행 중인 KeyLens 금고에서 그때그때 값을 받아옵니다. 

# 설치 (PyPI 아님 — 저장소에서 바로)
pip install "git+https://github.com/ttogle918/key-manager.git#subdirectory=keylens-env"

# 프로젝트 루트에 .keylens.toml
project = "블로그"

# 코드에서
import keylens_env
keylens_env.load_env()
os.environ["OPENAI_API_KEY"]

프로젝트마다 접근 범위가 나뉩니다. 등록되지 않은 디렉토리가 키를 요청하면 KeyLens 창에 승인 팝업이 뜨고, 허용한 프로젝트의 키만 내려갑니다.
